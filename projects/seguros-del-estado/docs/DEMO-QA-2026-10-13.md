# Guía de demostración — SDE-CEL (13 de octubre de 2026)

Todos los comandos se verificaron el 2026-10-13 en **PowerShell** sobre este repositorio, con `--list` para confirmar qué pruebas selecciona cada uno. Se ejecutan desde la **raíz del repositorio**:

```powershell
Set-Location "<ruta-del-repositorio>"
```

## 0. Reglas para que los comandos funcionen en Windows (comprobadas)

| Regla | Por qué |
|---|---|
| Usar `node tools/run.mjs seguros-del-estado …`, **no** `npm test -- …` | Desde PowerShell, `npm test -- … --grep "@X"` **no selecciona ninguna prueba** (verificado) |
| Poner siempre entre comillas el valor de `--grep`: `--grep "@HU06-CP05"` | Sin comillas PowerShell interpreta `@...` como *splatting* y lo borra (verificado: 0 pruebas) |
| No usar espacios ni `\|` en los filtros | `tools/run.mjs` lanza Playwright a través de `cmd.exe`: un espacio convierte la segunda palabra en otro filtro, y `\|` rompe el comando |
| Filtrar archivos por nombre completo: `variantes.real`, no `variantes` | `variantes` también selecciona `secuencia-variantes.unit.spec.ts` |
| Activar las variables con `$env:VAR="1"` y quitarlas al terminar con `Remove-Item Env:VAR` | Las variables quedan activas en la ventana de PowerShell y activarían pruebas que crean casos |
| Mantener `--workers=1 --trace off` en todo lo que toca QA | Un solo navegador a la vez; sin trace, que guardaría la clave tecleada |

Por defecto el navegador se ve en pantalla (Edge), lo que sirve para mostrar el recorrido.

## 6. Cómo leer los resultados

Playwright muestra **passed / failed / skipped**, que es el resultado *técnico*. El resultado *funcional* del CP aparece en el resumen de consola y en el reporte JSON:

| Estado funcional | Significado | Cuenta como aprobado |
|---|---|---|
| **REAL_PASS** | Sesión y caso reales, y **todos** los pasos de la matriz verificados | Sí |
| **REAL_PASS_PARCIAL** | Sesión y caso reales, sin fallos, pero hay pasos no observables o no automatizables (p. ej. Worker AI) | **No** (Playwright lo muestra como *passed*) |
| **BLOCKED** | Faltan datos, credenciales o permisos del ambiente. La prueba no corre o se detiene sin culpa del producto | No (aparece como *skipped* o *failed*) |
| **FAIL** | Un paso de la matriz no se cumplió en QA | No |
| Paso **INTEGRATION_NOT_VERIFIED** | El paso depende de SISE o del Worker AI y no hay forma de observarlos | — |
| Paso **NOT_AUTOMATED** | El paso no tiene criterio objetivo (p. ej. ortografía global sin glosario) | — |
| Reporte **VARIANTE_** | Secuencia distinta de la aprobada en la matriz, para comparar | **Nunca** |
